# Partner Funnel Lab: the experiments half of partnerflow-lab

Run everything below from this `experiments/` folder; it is a self-contained Python project with its own `pyproject.toml`.

A simulated partner-referred lending funnel, inspired by embedded-lending partner
funnels. All customers, partners and outcomes are simulated. Known effects let
us test whether statistical methods recover the intended quantities.

## Run locally

Use Python 3.12 and run commands from this repository. With `uv` installed:

```sh
UV_CACHE_DIR=.cache/uv uv sync --locked
.venv/bin/python -m sim.generate --seed 0
.venv/bin/python -m pytest tests -q --method-results=data/method-results.json
.venv/bin/python -m analysis.report
.venv/bin/python -m uvicorn api.main:app --host 127.0.0.1 --port 8000
```

The API docs are at <http://127.0.0.1:8000/docs> and health at
<http://127.0.0.1:8000/health>. Generate data before starting the API: it loads
`data/events.parquet` once at startup. Restart it to load regenerated data.
TestClient checks require no running server. The hierarchy uses two sequential,
seeded chains; its portable Python execution can take several minutes. A working
C++ setup can opt into compilation via `PYTENSOR_FLAGS`.

```sh
curl http://127.0.0.1:8000/v1/funnel/7
curl -X POST http://127.0.0.1:8000/v1/experiments/power \
  -H 'Content-Type: application/json' \
  -d '{"baseline_rate":0.16,"mde_pp":4,"daily_traffic":100}'
curl -X POST http://127.0.0.1:8000/v1/experiments/analyse \
  -H 'Content-Type: application/json' \
  -d '{"control":{"n":1500,"conversions":240},"treatment":{"n":1500,"conversions":300},"planned_n_per_arm":1500}'
```

Power traffic is total eligible arrivals across both arms. Recruitment days
exclude the 90-day outcome delay. The sample-size readiness flag does not certify
outcome maturity. This retrospective simulation includes follow-up through day
229 for arrivals on days 0–139. Contracts and rate denominators are in
[SCHEMA.md](SCHEMA.md); implementation decisions are in [NOTES.md](NOTES.md).

The biased before/after estimates are intentional negative controls: their tests

seeded repeated experiments, with achieved power within 3 percentage points of
80%; it is a design calculation, so it has no effect-estimate row.

## Learning

This lab demonstrates why an observed increase is not automatically an
intervention effect. Staggered rollout correlated with partner size and a time
trend confound the pooled before/after comparison. Randomisation isolates the
top-up effect within eligible customers. Partner and day fixed effects separate
stable partner differences and common time changes in this simulator, while a
separate indicator accounts for partner 7's launch. Hierarchical partial pooling
shares information across partners to estimate baseline conversion rates with
uncertainty. Ground truth makes these ideas testable here; success on one
simulated seed does not establish validity on real lending data.

### ML/DS learning log

These are project lessons and exercises, not a claim of personal mastery.

| Topic | Evidence in the project | Interpretation or limitation |
|---|---|---|
| Reproducible simulation | Seeded arrivals, effects and nested funnel outcomes; byte-identical repeated output test | Truth recovery depends on the chosen data-generating process. |
| Power and MDE | Two-proportion planning, checked by Monte Carlo experiments | Smaller detectable effects require more observations; recruitment and follow-up are separate. |
| Randomised A/B | Eligible notified and unnotified arms; Wilson-based interval and Beta-posterior comparison | Bayesian probability of improvement and a frequentist p-value answer different questions. |
| Confounding | Before/after tests assert bias exceeds 1.5pp | Narrow uncertainty around a biased estimate does not fix the design. |
| Difference in differences | Arrival-weighted partner/day fixed effects, partner-clustered uncertainty | Recovery relies on this simulator's homogeneous effects and modelled launch; staggered TWFE need not work with heterogeneous effects. |
| Partial pooling | Joint Beta prior and partner Binomial observations on untreated days 0–27 | The reported mean weights partners equally, unlike a traffic-weighted overall conversion. |
| Calibration and diagnostics | True rates checked against 94% partner intervals; R-hat, ESS and divergences tested | Coverage across 40 partners is coarse and is not repeated-simulation calibration. R-hat checks chain agreement; ESS measures effective posterior sample size. |
| Serving analysis | Pydantic contracts, FastAPI and TestClient | API schema correctness and estimator correctness require separate checks. |

## Scope and stopping point

GOAL includes the simulator, power, A/B, biased benchmark, DiD, hierarchy, four
API endpoints, tests and this generated report. See [PLAN.md](PLAN.md) for status
